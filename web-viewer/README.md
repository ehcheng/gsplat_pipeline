# Web viewer and publishing

This folder turns a full-quality Gaussian-splat PLY into a compact SOG scene in a self-hosted browser viewer (PlayCanvas SuperSplat), and serves it from a Cloudflare Worker at `/3d/<slug>/` on your domain, publicly or behind a per-scene password.

For the complete workflow of adding, replacing, protecting, testing and removing scenes, see [PUBLISHING.md](./PUBLISHING.md). For handing the scene list to another website, see [CATALOG.md](./CATALOG.md).

## Setup

```powershell
pnpm install
```

Your site's settings live outside this folder, in `site/` at the repository root (gitignored): `wrangler.jsonc` (Cloudflare account, routes, site name, Turnstile key) and `scenes.json` (the scene registry). Start from the template:

```powershell
Copy-Item -Recurse ..\site.example ..\site
```

Set `GSPLAT_SITE_DIR` to keep the site folder somewhere else, for example in its own private repository. Every Wrangler command goes through `scripts/wrangler.mjs`, which adds `--config ../site/wrangler.jsonc` and keeps the Cloudflare login in this folder's `.wrangler-config/`.

| Command | Does |
| --- | --- |
| `node scripts/frame.mjs <scene>` | Level the scene, propose opening views, render the share thumbnail |
| `node scripts/build-viewer.mjs <ply> <slug>` | Build `dist/3d/<slug>/` and its `/vr` variant |
| `node scripts/wiggle.mjs <scene>` | Render the looping landing-page clip |
| `node scripts/export-bridge.mjs <folder>` | Write the catalog for a host site (optional) |
| `pnpm run whoami` / `check:deploy` / `deploy` | Wrangler, against the site config |
| `pnpm run preview` | Run the Worker locally (`wrangler dev`) |
| `pnpm run auth:init` | Store the Turnstile secret and a generated session key (protected scenes) |
| `pnpm run password:set -- <slug>` | Set a protected scene's password at Wrangler's masked prompt |
| `node scripts/viewer-patch.mjs` | Re-patch every built scene after a viewer upgrade or tuning change |

Each build also writes `dist/3d/<slug>/vr/`, a 350 k splat version for Quest and phone AR that is served at `/3d/<slug>/vr/` with the viewer's AR/VR buttons (the main page hides them). See PUBLISHING.md for the options.

## Password gate

The Worker in `src/index.js` runs before every static asset request under `/3d/`. Scenes registered with `passwordBinding: null` are public. A protected scene shows a login page with a Cloudflare Turnstile check, compares the password with that scene's own Worker secret using a timing-safe digest comparison, and issues a scene-specific, signed, HTTP-only session cookie. Direct requests for a protected `scene.sog` require the same session as the page. Unregistered slugs return 404 even if their files are in `dist`.

Protected scenes need these encrypted Worker secrets:

- `SPLAT_PASSWORD_<SLUG>`: one per protected scene (`my-scene` → `SPLAT_PASSWORD_MY_SCENE`)
- `SESSION_SECRET`: generated by `pnpm run auth:init`
- `TURNSTILE_SECRET_KEY`: from your Turnstile widget, entered at `pnpm run auth:init`

The public Turnstile site key goes in `TURNSTILE_SITE_KEY` under `vars` in `site/wrangler.jsonc`. The viewer pages also send `noindex`/`nofollow`, but those are discovery hints, not authentication; the Worker is the access boundary.

### Reliable secret entry on Windows

- Run Wrangler through `scripts/wrangler.mjs` (or the `pnpm run` scripts), which pins `XDG_CONFIG_HOME` to this project's `.wrangler-config`. A new shell may otherwise pick up a different, unauthenticated Cloudflare profile.
- Use Wrangler's native `secret put` masked prompt. A custom Node/readline masked-input wrapper proved unreliable on Windows and produced misleading rejection messages.
- Confirm the account with `pnpm run whoami` before entering secrets. Secret writes need the `workers:write` OAuth scope in addition to the narrower script and route scopes.
- Verify by listing binding names only (`pnpm run wrangler -- secret list`). Never print, log or paste secret values.

## Controller (gamepad) behaviour

The stock SuperSplat viewer turns at about 9 degrees per second on a gamepad and walks at the un-boosted keyboard speed, far below what a console shooter does. `scripts/viewer-patch.mjs` replaces the viewer's `GamepadDevice` class when `build-viewer.mjs` copies the bundle, giving FPS-style rates:

| Input | Behaviour |
| --- | --- |
| Right stick | Look, FPS convention (push forward to look up; see Invert Y-Axis below), at 126 deg/s yaw and 95 deg/s pitch at full deflection (at a 90 degree FOV; scaled by the current FOV so on-screen speed is constant), plus Halo-style look acceleration of +56/+42 deg/s after half a second at full deflection. Orbit mode uses 0.6x of that. |
| Left stick | Move at 1.5x the keyboard's base speed |
| L3 or RT | Sprint (x2 walk, x4 fly, matching Shift) |
| LT | Precision (x0.5 walk, x0.25 fly, matching Ctrl) |
| RB / LB | Fly up / down |
| A | Jump (walk mode) |

Sticks get a 12 percent radial dead zone and a 1.5-power response curve. Reference points: Halo CE default sensitivity measures 114 to 234 deg/s with acceleration, Borderlands 90 to 135 deg/s, Apex ALC defaults are in the same range. The numbers are fields at the top of the class in `scripts/viewer-patch.mjs`.

Every device starts in Orbit around the opening camera's target: drag orbits the subject, two fingers or right-drag pan, pinch or wheel zooms. On the keyboard, W/A/S/D + Q/E move and I/J/K/L turn the view like a digital right stick, so the keyboard alone can fly two-handed; any of those keys switches Orbit to Fly.

The patch also adds an **Invert Y-Axis** switch to the viewer's settings panel (gear icon), below the stock toggles. It is off by default and remembered per browser in `localStorage` (`invertLook`). It flips vertical look for the gamepad right stick in every mode and for the mouse in Fly and Walk. Orbit dragging and touch are direct manipulation and are not affected.

After upgrading `@playcanvas/supersplat-viewer`, or after changing the tuning, refresh every built scene without reconverting and deploy:

```powershell
node scripts\viewer-patch.mjs
pnpm run deploy
```

The patch is anchored on exact code shapes and refuses to run if a viewer upgrade changes them, so a layout change fails the build instead of silently shipping stock behaviour.
