# gsplat catalog handoff

How the 3D Gaussian-splat captures ("gsplats") are hosted at `{{SITE}}/3d/`, and how a host site (a blog, portfolio or media library) can list them as a content category.

This file is `HANDOFF.md` in the bridge folder. It is generated by `web-viewer/scripts/export-bridge.mjs` from `web-viewer/CATALOG.md` (or from `site/HANDOFF.md` when the site folder has its own version); edit it there, not in the bridge folder.

## TL;DR for the host site's build

1. Read `gsplats.json` from the bridge folder at build time. It is the complete, current catalog. Anything not in it has been removed.
2. For each item, show a card **unless `unlisted` is true**. The card links to `item.url` (`{{SITE}}/3d/<slug>/`), which is served by a Cloudflare Worker, not by the host site.
3. Import the thumbnails from `thumbnails/<slug>/` into your own image pipeline. Do not hotlink them from `/3d/`: protected scenes' images are not public there.
4. For `protected: true` items, mark the card as password-protected and decide whether to show the real thumbnail or a generic one (see [Protected and unlisted](#protected-and-unlisted)).
5. Do not serve anything at `/3d` or under `/3d/` from the host site. Those paths belong to the Worker, which redirects `/3d` and `/3d/` to the Worker's `GSPLAT_INDEX_URL` (your category page) when it is set.

## Files in the bridge folder

| Path | What it is |
| --- | --- |
| `gsplats.json` | The catalog. One item per published scene. Written atomically (temp file + rename), always last, so a reader never sees a half-written file. |
| `gsplats.schema.json` | JSON Schema (draft 2020-12) for `gsplats.json`. Validate against it in your build. |
| `thumbnails/<slug>/master.jpg` | The source thumbnail: 1920×1280 (3:2) JPEG. |
| `thumbnails/<slug>/<ratio>-<width>.webp` | Ready-made crops of the master (see [Thumbnails](#thumbnails)). |
| `previews/<slug>.mp4` | A silent, seamlessly looping 1920×1080 clip of the scene with a small camera "wiggle" (see [Preview clips](#preview-clips)). |
| `HANDOFF.md` | This document. |

Nothing else in the folder is part of the contract.

## How the scenes are hosted

| Path | Response |
| --- | --- |
| `/3d/<slug>/` | The viewer page (PlayCanvas SuperSplat viewer). Public scenes: served directly. Protected scenes: 303 to the login page unless the visitor has that scene's session cookie. |
| `/3d/<slug>/vr/` | A lighter build of the same scene for VR headsets and phone AR, behind the same access rule. Not listed in the catalog. |
| `/3d/<slug>/login` | Password page for a protected scene (Cloudflare Turnstile + a per-scene password). A good login sets a per-scene, HTTP-only cookie and returns to the scene. |
| `/3d/<slug>/logout` | POST ends that scene's session. |
| `/3d/<slug>/og.jpg` | 1200×800 link-preview image. Public without a session for public scenes; behind the login for protected ones. |
| `/3d/<slug>/scene.sog`, `index.js`, … | Viewer assets, same access rule as the page. |
| `/3d` and `/3d/` | 302 to `GSPLAT_INDEX_URL` when set, otherwise 404. The Worker never lists scenes itself. |
| anything else under `/3d/` | 404 |
| any `http://` URL under `/3d` | 308 to the same URL on `https://` |

Every response under `/3d/` carries `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer`. For the host site this means:

- **No iframes.** Link to the viewer instead; it also needs the whole window for pointer lock, gamepad and fullscreen. `scene.embeddable` is `false` for this reason.
- **Search engines do not index the viewer pages.** "Listed" means listed on the host site, not in search engines. The host site's own category and card pages can be indexed.
- **Link previews are handled.** Public scenes unfurl with title, description and `og.jpg`; protected scenes with title and a generic line, no image.

## gsplats.json

Top level: `schemaVersion` (`1`; bumped only for breaking changes), `generatedAt` (changes on every export; use each item's `revision` to detect real changes), `site` (`{{SITE}}`), `basePath` (`/3d/`), `count`, and `items` (newest capture first: `date` descending, then `slug`).

Per item:

| Field | Type | Meaning / how to use it |
| --- | --- | --- |
| `slug` | string | Stable id: lowercase letters, digits, single hyphens. Use it as your key. A changed slug is a new URL, so treat it as a new item. |
| `url` | string | Absolute viewer URL, always with trailing slash. The card's link target. |
| `title` | string | Display title. |
| `description` | string | One factual sentence (subject, and place when known). Also the thumbnail alt text. |
| `date` | `YYYY-MM-DD` | Capture date. |
| `protected` | boolean | `true`: the viewer asks for a password. Mark the card. |
| `unlisted` | boolean | `true`: omit from the public library, category page, site search, sitemaps and feeds. The scene is still reachable by anyone who has the link. |
| `location` | object or null | Where the scene was shot, entered by hand; `null` if not recorded. `name` is the place label, `locality` the city and region, `precision` is `exact` or `city`. `lat`, `lng` and `mapsUrl` are `null` for `city` precision and **always** `null` for protected scenes. |
| `thumbnail.alt` | string | Alt text (same as `description`). |
| `thumbnail.width/height/aspectRatio` | | Master is always 1920×1280, `3:2`. |
| `thumbnail.focalPoint` | `{x, y}` 0–1 | Where to center crops of the master. Defaults to the image center. |
| `thumbnail.sha256` | hex | SHA-256 of `master.jpg`: a content address and the change signal for the image. |
| `thumbnail.servedPublicly` | boolean | Whether the gsplat site itself publishes this image (`og.jpg`). `false` for protected scenes unless they opt in. |
| `thumbnail.publicUrl` | string or null | The public `og.jpg` URL (versioned by `?v=`) when `servedPublicly`. |
| `thumbnail.variants` | object | `master` plus the crops below. Each has `path` (relative to the bridge folder), `format`, `width`, `height`, `bytes`, `sha256`. |
| `preview` | object or null | The landing-page clip, `null` until rendered. `preview.video` is a file record; `codec` is `h264`; `durationSeconds`, `fps`; `loop: true` means the last frame leads into the first; `silent: true`; `poster` names the thumbnail variant to show until playback starts. |
| `scene.format` | string | `sog` |
| `scene.bytes` | integer | Size of the scene download (for a "20 MB" hint on mobile). |
| `scene.splatCount` | integer or null | Number of Gaussians. |
| `scene.openingFovDeg` | number or null | Vertical FOV of the viewer's opening camera (and of the thumbnail). |
| `scene.viewer` | string | Viewer package and version. |
| `scene.embeddable` | boolean | `false` (see above). |
| `builtAt` | ISO 8601 | When the scene's viewer bundle was last built. |
| `revision` | 16 hex | Hash of everything else in the item. Unchanged means nothing about the item changed. |

## Thumbnails

Each scene is rendered at 3840×2560 from the viewer's opening camera with a rectilinear lens, then downsampled to 1920×1280, so the thumbnail matches what a visitor sees when the viewer opens.

| Variant | Size | Suggested use |
| --- | --- | --- |
| `master` | 1920×1280 JPEG | Source for your own image pipeline |
| `3x2-1920`, `3x2-960`, `3x2-480` | 3:2 | Cards and search results (`srcset`) |
| `16x9-1920`, `16x9-960` | 16:9 | Heroes and headers |
| `21x10-1680`, `21x10-840` | 21:10 | Wide landing-page rows |
| `1x1-1024`, `1x1-480` | 1:1 | Grid cells |

All variants are WebP (quality 82), cropped around `focalPoint`. If your pipeline makes its own sizes, use `master.jpg` with `focalPoint` and ignore the WebP files. Copy the files into your own asset store; do not reference the bridge folder at runtime.

## Protected and unlisted

The two flags are independent:

| `protected` | `unlisted` | On the host site |
| --- | --- | --- |
| false | false | Card in the library, category and search, with the real thumbnail. |
| true | false | Card shown and **marked as password-protected**. Thumbnail: your call, see below. |
| false | true | Not in the library, category, search, sitemap or feeds. Direct link only. |
| true | true | Not listed anywhere; direct link plus password. |

The bridge includes the real thumbnail and clip of every scene, protected ones too, but the gsplat site does not publish protected scenes' images. Publishing them on the host site would show a still from a private scene to anyone, so default protected cards to a generic image and use the real one only when `thumbnail.servedPublicly` is `true` (the scene opted in with `socialImage: true`).

## Preview clips

Play `previews/<slug>.mp4` where the still thumbnail would otherwise sit, so motion parallax is visible before anyone opens the viewer: `<video autoplay muted loop playsinline preload="metadata" poster="...">` with the `16x9-1920` thumbnail as poster. Respect `prefers-reduced-motion` by showing the poster only. Read `fps` and `durationSeconds` from the item rather than assuming them. Serve the clip from your own asset store; the same protected/unlisted rules apply as for thumbnails.

## Updates and sync

- **Source of truth:** the site registry (`site/scenes.json` in the gsplats repository). The Worker serves from the same file, so the catalog and the live site cannot disagree on who is protected.
- **Export:** after every deploy, `node scripts/export-bridge.mjs <bridge folder>`. It refuses to run (leaving the previous catalog untouched) if any registered scene is unbuilt, has no thumbnail, or lacks a required field.
- **On the host site:** treat `gsplats.json` as a full snapshot. Upsert by `slug`, skip items whose `revision` is unchanged, and remove records whose slug has disappeared. Thumbnails and clips of removed scenes are deleted from the bridge by the export.
- **Change signals:** `revision` (anything about the item), `thumbnail.sha256`, `preview.video.sha256`, `builtAt`.
